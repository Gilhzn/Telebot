# Stock News Radar 📡

בוט טלגרם אישי שסורק את השוק האמריקאי ושולח **רק חדשות חיוביות מאוד** למניה, שניות אחרי הפרסום הרשמי:
זכייה בחוזה גדול, החברה נרכשת, אישור FDA, שותפות עם ענקית, העלאת תחזית.

הבוט הולך ישר למקורות הראשוניים, בלי ערוצי ביניים:

| מקור | תדירות |
|---|---|
| SEC EDGAR, פיד חי של 8-K ו-6-K (כולל ההודעה לעיתונות EX-99.x) | כל 2 שניות |
| PR Newswire, GlobeNewswire, Business Wire (16 פידי RSS) | כל 10 שניות |
| מיפוי טיקרים של ה-SEC | פעם ביום |

רק מניות שנסחרות בבורסות בארה"ב (NASDAQ, NYSE, NYSE American, CBOE). ההתראות בעברית, לצ'אט פרטי אחד.

> ℹ️ מידע פומבי בלבד, לא ייעוץ השקעות. ידיעה חיובית לא מבטיחה עלייה, ומניות קטנות נוטות לקפוץ ולחזור.

## איך זה עובד

```
ידיעה חדשה → בחירת מועמדים → פסילה לפי מילים שליליות → דירוג (כללים / Claude)
          → ציון ≥ MIN_SCORE? → מניעת כפילות לטיקר (6 שעות) → טלגרם
```

- **בחירת מועמדים**: 8-K עם Item 1.01 / 2.01 / 2.02 / 7.01 / 8.01, כל 6-K, וכל הודעה לעיתונות עם טיקר של בורסה אמריקאית, למשל `(NASDAQ: OKLO)`. מניות ברשימת המעקב תמיד נבדקות.
  דיווחי EDGAR של חברות שלא רשומות בבורסה אמריקאית (OTC, חברות פרטיות) מדולגים, ותיקונים (8-K/A) לא נבדקים.
- **פסילה**: הנפקה ודילול, reverse split, אזהרות מחיקה, going concern ופשיטת רגל, תביעות ו-investor alert, הצגה מחדש של דוחות, הורדת תחזית, clinical hold ו-CRL, התפטרויות ופיטורים.
  הפסילה והדירוג בכללים נעשים על הכותרת ותחילת ההודעה, אחרי חיתוך של "About…", Forward-Looking Statements ואנשי קשר, כדי שהסתייגויות משפטיות סטנדרטיות לא יפסלו ידיעה טובה.
- **דירוג בכללים** (ברירת מחדל): כל ביטוי חיובי מוסיף נקודות (למשל `to be acquired by`, `FDA approval` = 5, `per share in cash`, `raises guidance` = 4, `awarded` = 3, לקוח ממשלתי = 2), בונוס +2 על חברת ענק ו-+1 על סכום של 100 מיליון דולר ומעלה. מקסימום 5.
- **דירוג עם Claude** (כש-`ANTHROPIC_API_KEY` מוגדר): רק ידיעות עם ציון כללים 1 ומעלה (או מניות במעקב) נשלחות ל-`claude-haiku-4-5-20251001`, עד 5 במקביל. אם הקריאה נכשלת, הבוט משתמש בציון הכללים.

- **קטליזטורים צפויים**: כשחברה מודיעה מראש על תאריך, למשל "Kodiak Sciences to Present Topline Results on September 28", הבוט שולח הודעת 📅 עם התאריך ומוסיף את המניה לרשימת המעקב. ביום עצמו, מ-04:00 שעון ניו יורק (פתיחת ה-pre-market), הוא שולח תזכורת ⏰. הבוט מזהה שלושה סוגים: תוצאות ניסוי קליני (topline / pivotal / Phase 2-3), תאריך PDUFA של ה-FDA, וועדה מייעצת של ה-FDA. הודעות על מועד דוחות כספיים לא נחשבות קטליזטור. `CATALYST_ALERTS=false` מכבה את התכונה.
- **אזהרת פמפום / סיכון התרסקות**: לכל התראה חיובית הבוט בודק את היסטוריית הדיווחים של החברה ב-SEC ואת נוסח הידיעה, ומוסיף שורה ⚠️ כשיש סימנים לכך שהעלייה עלולה להתהפך: מדף הנפקה או תשקיפי מכירה (S-1/S-3/424B) בשנה האחרונה, שכן החברה יכולה למכור מניות לתוך העלייה; אזהרת מחיקה מהבורסה (Item 3.01); מכירת מניות פרטית (Item 3.02); איחוד מניות (reverse split); איחור בדוחות (NT); הסכם לא מחייב (MOU / LOI / term sheet); סכום "עד $X"; או מילות קריפטו/טרז'רי. 🔴 פירושו סיכון גבוה ו-🟠 סיכון בינוני. זו הערכה היוריסטית, לא תחזית. הבדיקה מוגבלת ל-4 שניות, ואם ה-SEC לא עונה ההתראה נשלחת בלי השורה. `PUMP_CHECK=false` מכבה את התכונה.
- **מבחן חי (דוח ביצועים)**: כל התראה שנשלחת נרשמת. בכל יום מסחר ב-20:10 שעון ניו יורק, אחרי סוף המסחר המאוחר, הבוט בודק כל התראה כאילו קנית אותה בדיוק 3 דקות אחרי שנשלחה: מחיר הכניסה, השינוי אחרי 5 דקות, 30 דקות ושעה, בסגירה, ובאסטרטגיית יעד +2% / סטופ -2%. הבדיקה נעשית על נרות של דקה מ-Yahoo. בנוסף הוא שולח סיכום מצטבר לפי $2,000 לעסקה, ברוטו ונטו אחרי 1% עלויות, ולפי רמת אזהרת הפמפום. `/perf` מציג את המצטבר בכל רגע.
- **בקטסט על העבר**: `tools/backtest.py` מריץ את אותו חישוב על דיווחי SEC מהעבר. ה-workflow ‏`backtest-recent` בודק 57 ימים אחורה בחינם. לתקופות ישנות יותר צריך מפתח Alpaca.
- **תיקי משקיעי-על (13F)**: הבוט עוקב אחרי הדיווחים הרבעוניים ל-SEC של עשרה משקיעים מוכרים. אלה הנתונים ש-GuruFocus מציג בעמוד top-holdings: Warren Buffett, Bill Ackman, Michael Burry, Seth Klarman, David Tepper, Stanley Druckenmiller, Li Lu, Bill Gates, Howard Marks ו-Ray Dalio. כל 30 דקות הוא בודק אם הוגש דיווח חדש. אם כן, הוא משווה אותו לרבעון הקודם ושולח הודעה: מה קנו (פוזיציות חדשות), מה הגדילו, מה הקטינו ומה מכרו לגמרי, עם טיקר (דרך OpenFIGI) וקישור לדיווח עצמו. `/gurus` מציג את הרשימה. `GURUS` מחליף את הרשימה (פורמט `CIK:שם:קרן`, מופרד בפסיקים), ו-`GURU_ALERTS=false` מכבה את התכונה. GuruFocus עצמו חוסם קריאה אוטומטית, ולכן הנתונים נלקחים ישירות מה-SEC.
- **לימוד מניות מזנקות**: בכל יום מסחר ב-20:20 שעון ניו יורק הבוט סורק את כל המניות הרשומות בבורסות בארה"ב דרך Yahoo, כ-20 מניות בכל בקשה, ומוצא את אלה שעלו 20% ומעלה. לכל אחת הוא מחשב מנרות של דקה מתי הזינוק התחיל ומה השיא. הוא מוצא את הידיעה המוקדמת ביותר שקדמה לזינוק, מהלוג של הבוט עצמו או מחדשות Yahoo, כולל המפרסם ושעת הפרסום המדויקת. הוא מסמן אם המקור הוא כזה שהבוט לא קורא, ובודק אם הבוט התריע ומתי. סיכום יומי נשלח לטלגרם. `/learn` מציג מה נלמד: איזה סוג חדשות מקפיץ מניות, איזה מקור מגיע ראשון, כמה זינוקים הם בלי חדשות, ואיזה אחוז הבוט תופס לפני תחילת הזינוק. אחרי 10 ימי מסחר נשלחת הודעת "אני מוכן" עם הסיכום. `tools/gainers.py history 30` מריץ את המחקר על 30 ימי המסחר האחרונים. Nasdaq לא בשימוש, כי הוא חוסם לקוחות שמזדהים ביושר כבוט.

## הרצה מקומית

דורש Python 3.12 (עובד גם על 3.10 ומעלה).

```bash
# 1. טוקן: @BotFather → /newbot  (אם טוקן נחשף אי פעם: /revoke והנפקה מחדש)
cp .env.example .env        # למלא TELEGRAM_BOT_TOKEN ו-SEC_USER_AGENT
pip install -r requirements.txt

python bot.py --test        # בודק טוקן, מזהה ושומר chat id, שולח התראת דוגמה
python bot.py               # הרצה רציפה
```

בהפעלה נשלחת הודעת "פעיל". בהרצה הראשונה כל מה שכבר קיים בפידים מסומן כ"נראה" בלי שליחה, כדי לא להציף.

## פריסה

| | שרת (Railway / Oracle) | GitHub Actions |
|---|---|---|
| עיכוב התראה | 2 עד 10 שניות | 2 עד 15 שניות (ריצה רציפה); כדקה פעם בשעה, במעבר בין ריצות |
| פקודות טלגרם | מיידי | מיידי |
| עלות | Oracle חינם, Railway כ-5$ לחודש | חינם בריפו ציבורי; בריפו פרטי לבדוק מול מכסת הדקות |

**המלצה: שרת.** זו הדרך היחידה לעמוד במטרה של "לפני כולם".

### Railway
1. https://railway.com → Login with GitHub → **New Project** → **Deploy from GitHub repo** → `Gilhzn/Telebot`.
2. בשירות שנוצר, בלשונית **Variables**: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `SEC_USER_AGENT`, `STATE_FILE=/data/state.json`, `PYTHONUNBUFFERED=1` (ואופציונלית `ANTHROPIC_API_KEY`).
3. **Volume**: קליק ימני על השירות (או Ctrl+K) → Add Volume → Mount path `/data`. כך המצב נשמר בין הפעלות.
4. **Settings → Source**: לוודא שהענף הוא ענף ברירת המחדל של הריפו.
5. אחרי הפריסה תגיע לטלגרם הודעת "🟢 פעיל". פקודת ההרצה מגיעה מ-`railway.json` (`python bot.py`, הפעלה מחדש אוטומטית).
6. **לכבות את GitHub Actions** כדי שלא יהיו התראות כפולות: להשבית את ה-job ב-cron-job.org, ולמחוק את המשתנה `RADAR_MODE` ב-GitHub (Settings → Secrets and variables → Actions → Variables).

### Oracle Cloud (או כל שרת Ubuntu)
למלא את המשתנים בראש `oracle-cloud-init.sh` ולהדביק אותו כ-cloud-init ביצירת המכונה (Ubuntu 24.04), או להריץ `sudo bash oracle-cloud-init.sh` על מכונה קיימת.
הסקריפט מבצע `git clone` מהריפו, מתקין venv ושירות systemd (`journalctl -u stock-news-radar -f` ללוגים). הרצה חוזרת מושכת את הקוד העדכני ומפעילה מחדש.

### GitHub Actions (ריצה רציפה)
כל הרצה של ה-workflow מפעילה `python bot.py --run-for 3600`: הבוט סורק ברציפות במשך שעה, כמו על שרת (SEC כל 2 שניות, פידי ההודעות הראשיים כל 10 שניות, פידי הקטגוריות כל דקה), ואז יוצא. ההפעלה החיצונית (cron-job.org) משאירה תמיד הרצה אחת ממתינה בתור, ולכן ההרצה הבאה מתחילה מיד כשהקודמת נגמרת. `state.json` נשמר לענף `state` כל 5 דקות ובסוף כל הרצה.
- `RADAR_LOOP_MINUTES` (משתנה ב-Settings → Variables): אורך כל הרצה בדקות. ברירת המחדל היא 60, והמקסימום 80. הערך `0` מחזיר את המצב הישן: `python bot.py --once`, מעבר יחיד על כל המקורות ויציאה.
- שינוי בקוד נכנס לתוקף בהרצה הבאה, כלומר תוך שעה לכל היותר. כדי להחיל אותו מיד, מבטלים את ההרצה הפעילה (Cancel run).

ה-workflow ב-`.github/workflows/radar.yml` מבצע את ההרצה, ו-`.github/workflows/radar-schedule.yml` מפעיל אותו כל 5 דקות. את `state.json` הוא שומר בענף נפרד בשם `state`, כקומיט יחיד שמוחלף בכל הרצה, כך שהיסטוריית הקוד נשארת נקייה. הוא **כבוי כברירת מחדל**, כדי שלא ירוץ במקביל לשרת (שני קבצי מצב = התראות כפולות).

**הפעלה:**
1. **chat id:** פתח את הבוט בטלגרם ולחץ Start. אחר כך פתח בדפדפן את הכתובת `https://api.telegram.org/bot<TOKEN>/getUpdates`, כשבמקום `<TOKEN>` מופיע הטוקן שלך. המספר שמופיע אחרי `"chat":{"id":` הוא ה-chat id.
2. **סודות:** בריפו ב-GitHub, Settings → Secrets and variables → Actions → **Secrets** → New repository secret:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `SEC_USER_AGENT` (שם ואימייל)
   - `ANTHROPIC_API_KEY` (אופציונלי)
3. **הפעלת ה-workflow:** באותו מסך, בלשונית **Variables** → New repository variable: `RADAR_MODE` = `actions`.
4. **בדיקה:** בלשונית Actions → radar → Run workflow → mode = `test`. תוך דקה תגיע לטלגרם התראת דוגמה.
   `mode = diag` בודק את החיבור ל-PR Newswire ול-GlobeNewswire משרתי GitHub, בלי לשלוח כלום לטלגרם.
5. **הרצה ראשונה:** Run workflow → mode = `once`, או לחכות להרצה המתוזמנת. ההרצה הראשונה רק מאתחלת את הפידים ולא שולחת כלום. מההרצה השנייה מגיעות התראות, ו-`/status` בטלגרם יקבל תשובה בהרצה הבאה.

**הפעלה חיצונית (מומלץ):** המתזמן של GitHub לא אמין. הוא מתעכב לעיתים קרובות ב-10–30 דקות, ולפעמים לא מפעיל כלל workflow חדש. במקום לסמוך עליו, שירות חיצוני חינמי מפעיל את ה-workflow כל 5 דקות:
1. **טוקן GitHub מוגבל:** https://github.com/settings/personal-access-tokens/new → Fine-grained token.
   - Repository access: Only select repositories → `Telebot`.
   - Permissions → Repository permissions → **Actions: Read and write**. זו ההרשאה היחידה שצריך.
   - Generate token והעתקה.
2. **cron-job.org:** נרשמים בחינם ב-https://cron-job.org ויוצרים Cronjob חדש:
   - URL: `https://api.github.com/repos/Gilhzn/Telebot/actions/workflows/radar.yml/dispatches`
   - Schedule: Every 5 minutes
   - Advanced → Request method: **POST**
   - Advanced → Headers:
     - `Authorization`: `Bearer <הטוקן משלב 1>`
     - `Accept`: `application/vnd.github+json`
     - `X-GitHub-Api-Version`: `2022-11-28`
     - `Content-Type`: `application/json`
   - Advanced → Request body: `{"ref":"claude/stock-news-radar-bot-05owh7","inputs":{"mode":"once"}}`
3. **בדיקה:** ב-cron-job.org לוחצים Test run. תשובה `204` פירושה הצלחה, ובלשונית Actions מופיעה הרצה חדשה.

אם הענף ישתנה בעתיד (למשל מיזוג ל-`main`), צריך לעדכן את `ref` בגוף הבקשה. ה-cron של GitHub נשאר כגיבוי. שתי הפעלות אף פעם לא רצות במקביל (הגדרת concurrency), כך שלא נוצרות התראות כפולות.

**מגבלות:**
- GitHub לא מבטיח את התזמון של ה-cron הפנימי. לכן מומלצת ההפעלה החיצונית שלמעלה.
- השימוש ב-GitHub Actions להרצה רציפה של בוט הוא שטח אפור בתנאי השימוש של GitHub. שרת הוא הפתרון היציב לטווח ארוך.
- בריפו ציבורי GitHub משבית workflows מתוזמנים אחרי 60 יום בלי פעילות בריפו. אם זה קורה, מפעילים מחדש מלשונית Actions.
- הריפו ציבורי, ולכן הלוגים של ההרצות (כותרות הידיעות) ו-`state.json` (רשימת המעקב) גלויים לכולם. הסודות מוסתרים.
